# Outcome 0011 — Derive the change-record risk tier from paths until the package register exists

- Decision: 0011
- Status: observed
- Observed: 2026-09-13

## Expected

Chapter 6 becomes shippable now, with the prediction enforced today rather than
after item 10. The path table becomes a thing to maintain: an unclassified
package lands in `unknown` and demands a prediction until somebody classifies it.
The named reversal: *"If a later change removes `TIER_SOURCE` or the docstring's
statement, this record has been reversed in substance."*

## Actual outcome

Still standing, checked directly. `deployment/change_records.py:90` declares
`TIER_SOURCE: Final[str] = "path-prefix"` and line 196 puts it into every report,
so no consumer of a report can mistake the derivation for a register. The
docstring still states plainly that Chapter 1's register does not exist.

The intended direction of the error is visible in the data. In the branch's
change-record report, commits touching skills and audit documents classify as
`[unknown]` and are asked for a prediction, exactly as designed — `unknown`
outranking `presentation` in `TIER_ORDER` is what produces that, and it produces
it often enough to be slightly annoying, which is the sign it is working.

## Lessons

Naming the derivation inside the output was the whole trick. The risk this
decision was managing is not that path prefixes are a poor proxy — they are a
fine proxy — but that a report saying `[core]` would be read as *the register
says core*. `TIER_SOURCE` costs one field and removes that reading entirely.

The same move is available anywhere a placeholder produces authoritative-looking
output, and this repository has been bitten by the absence of it (§E20 corrected
a claim of exactly that shape). A stand-in that announces itself is not technical
debt in the usual sense; it is a correct interim answer.
