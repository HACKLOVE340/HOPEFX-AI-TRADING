# Outcome 0005 — Hand a child a grant instead of sharing a ledger

- Decision: 0005
- Status: observed
- Observed: 2026-09-13

## Expected

The bound holds across a process boundary with no shared state. A grant becomes
an explicit argument at every delegation site — "which is the point; an implicit
one is how a budget escapes."

## Actual outcome

Implemented as decided and still shaped that way. `ai/jobs/isolation.py:133`
declares `delegate(entrypoint, /, *, grant: int = 0, **args)` — keyword-only,
defaulting to zero — and `ai/jobs/lineage.py:116` carries `grant: int = 0` on the
lineage itself. The parent is charged `1 + grant` in full, so two siblings cannot
each be handed the remainder.

The default-zero choice is doing the work the record expected: delegation does
not propagate unless a caller said so, and every call site that wants propagation
has to say the word `grant=` out loud.

## Lessons

The keyword-only `*` in the signature is load-bearing and does not look it. A
positional grant would let an argument slide into that slot from a refactor, and
the whole guarantee is "nobody grants a budget by accident". That is worth a
comment at the signature, not only a record here.

As with 0004, this is verified-by-construction rather than verified-under-load.
The process boundary is crossed in tests and not yet in anger.
