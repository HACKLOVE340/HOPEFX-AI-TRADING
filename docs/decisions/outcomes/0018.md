# Outcome 0018 — A module unit tests import may not be excluded from coverage

- Decision: 0018
- Status: observed
- Observed: 2026-09-13

## Expected

Close the loophole that lets a module be excused from coverage while its own unit
tests import it — the case where exclusion is not "we cannot measure this" but
"we would rather not".

## Actual outcome

Holding, and inseparable from 0017's number: the same ratchet took the list from
249 to 228 entries between 2026-09-10 and 2026-09-13, and this rule is what stops
the easiest way of making that number fall without doing any work.

The mechanism is in `scripts/pre_commit_coverage.py` alongside 0017's, so there
is one gate rather than two that must agree. No module has been added to the
baseline while carrying a unit-test import since the rule landed.

## Lessons

This is the smaller and stricter half of 0017, and pairing them was right: a
baseline mechanism and the rule about what may enter it belong in the same gate,
because a rule enforced somewhere else is a rule that can be bypassed by using
the other entry point.

The honest caveat is that four days is a short observation window for a rule
whose whole purpose is to resist pressure. It will be tested the first time
somebody is in a hurry and a module they own is 40% covered. That is the review
this entry would want, and it is not scheduled by a date so much as by an
occasion — which is why it is recorded as a caveat here rather than as a
`pending` review nobody could act on.
