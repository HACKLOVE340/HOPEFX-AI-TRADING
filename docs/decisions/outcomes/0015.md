# Outcome 0015 — Adopt embedding-based news sentiment

- Decision: 0015
- Status: pending
- Review by: 2026-12-13

## Expected

Semantic recall for news sentiment, unblocking Group 3 item 13. Paid for with a
larger production image and a wider dependency surface, bounded by two
constraints that the record made part of the decision: **`faiss-cpu`, never
`faiss-gpu`**, and **the embedding model must not drag in `torch` unless measured
to be necessary.** Dropping either "reverses this decision in substance".

The record also states that the recommendation was to decline and was overruled
deliberately.

## Actual outcome

Partially adopted, and the dependency picture is more complicated than the record
assumed.

* **Constraint 1 holds.** `faiss-gpu` appears nowhere. `ml/advanced_ai.py`
  imports `faiss` optionally and, when it is missing, logs
  *"faiss-cpu not installed — vector RAG disabled"* and raises from
  `VectorRAGNewsSentiment` rather than degrading silently.
* **`faiss-cpu` is in no requirements file.** It is documented as a manual
  install (`ml/advanced_ai.py:61`). So the adopted feature is not installed in
  any environment this repository builds, and vector RAG is disabled everywhere
  today.
* **Constraint 2 needs restating rather than checking.** `torch>=2.1.0` is in
  `requirements-cpu.txt` and has been since commit `334e50f3`, 2026-08-13 —
  **four weeks before this decision.** The constraint was written to stop this
  adoption from pulling `torch` in; `torch` was already there, pulled by
  something else. Nothing was violated, and the cost the constraint was pricing
  had already been paid.

`sentence-transformers>=5.0.0,<6.0.0` is pinned in `requirements.txt` with a
comment about avoiding accidental GPU builds, which is constraint 1's spirit
applied to the second dependency.

## Lessons

Provisional, which is why this is `pending`: the feature has not run anywhere, so
its benefit is unobserved and its real image cost unmeasured.

One lesson is already firm. A dependency constraint should be stated against a
**measured** baseline, not an assumed one. "Must not drag in `torch`" reads as a
meaningful bound and was, at the moment it was written, describing a dependency
the image already had. The decision would have been taken on better information —
possibly the same way — had the requirements files been read first. The overrule
was deliberate and is recorded as such; the input to it was stale.

Review when `faiss-cpu` is actually in a requirements file and the index has run
against real news, or when it is clear it will not be — in which case supersede.
