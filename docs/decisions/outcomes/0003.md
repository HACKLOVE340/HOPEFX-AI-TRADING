# Outcome 0003 — Track prop_firm_mode.json with placeholder credentials

- Decision: 0003
- Status: observed
- Observed: 2026-09-13

## Expected

CI loads the real config shape. The active-by-default FTMO ruleset becomes
something a fresh deployment inherits, "which must be stated wherever the file is
described."

## Actual outcome

Both halves happened, and the second one needed chasing.

The file is tracked, carries placeholders only, and no real credential has ever
been committed to it. CI loads it.

The stated-wherever-described clause failed twice before it held. `CLAUDE.md`
said the file was gitignored — inviting exactly the thing the decision forbids,
putting real credentials into a tracked file — and **the file's own `_comment`
field said so too**, so a contributor who checked the source got the same wrong
answer. Both are corrected, and `CLAUDE.md` now states `enabled: true` with the
FTMO ruleset as an inherited default rather than leaving it to be discovered.

## Lessons

A decision whose safety depends on a sentence being repeated in three places has
three chances to be wrong, and the copy inside the artefact itself is the one
that looks most authoritative. The `_comment` field was believable precisely
because it was next to the data.

The decision's risk was never that someone would disagree with it; it was that
someone would not know it had been made. That is the failure mode of every
"placeholders only" convention, and it is why the statement lives in `CLAUDE.md`
and in the file rather than only here.
