# Modules with recorded coverage debt.
#
# ## What a line means, and what it used to mean
#
# It used to mean: no test file imports this module, so coverage collects no
# data. That reading was itself a casualty of a broken measurement. The gate
# invoked `pytest --cov=<dotted.module>`, which made coverage import the module
# and re-initialise numpy's C extension inside a process that had already
# imported numpy through tests/conftest.py:
#
#     ImportError: cannot load module more than once per process
#
# Every module in scope imports numpy transitively, so NOTHING could be
# measured. This list therefore records one broken invocation, not 361
# untested modules — and the header's old claim that "a baselined module at
# 25% still fails" described a comparison the gate was never able to make.
#
# The invocation is fixed (`--cov=<package>`, then the module's own row is read
# out of the report; see scripts/pre_commit_coverage.py and
# tests/unit/test_coverage_gate_can_measure.py). A line now means: this module
# is measurable, is below the floor, and that is recorded rather than blocking.
#
# ## The ratchet
#
#   * recorded + below the floor  -> reported as DEBT, does not block
#   * recorded + unmeasurable     -> reported as DEBT, does not block
#   * NOT recorded + below floor  -> blocks
#   * NOT recorded + unmeasurable -> blocks
#   * recorded + AT OR ABOVE floor -> BLOCKS, with one instruction: delete the
#     line. An entry that no longer describes anything is how a ratchet stops
#     being one.
#
# So this list SHRINKS by default, and it applies pressure in both directions.
# To remove an entry: raise that module's coverage past the floor, then delete
# its line. Enforced by tests/unit/test_coverage_gate_ratchet.py.
#
# ## The one way it grows, and why that is not a loophole — ADR 0017
#
# This paragraph used to say "may only SHRINK" full stop. That stopped being
# true on 2026-09-09, six entries ago, and the note further down already said
# so — a header that contradicts its own file is the exact defect this
# programme keeps removing, so it is corrected here rather than left to read
# as a rule nobody follows.
#
# The baseline was adopted from a SUBSET of the repository. A module outside
# that subset is not "new debt": it was already below the floor, unrecorded
# only because the seed never looked at it. When someone touches such a file
# the gate blocks their commit whatever the change, which turns the ratchet
# from "debt may only shrink" into "you may not touch an untested file" — and
# the documented escape from that is SKIP_COVERAGE_GATE=1, which is worse in
# every way.
#
# So an entry may be ADDED only when all of these hold, and the entry says so:
#
#   1. the module was ALREADY below the floor before the change — proven on a
#      clean tree or a worktree, not asserted;
#   2. the change does not LOWER its coverage;
#   3. the measured number is written down beside it; and
#   4. the owner has agreed, or an ADR records the standing agreement.
#
# Growth under those four is recording pre-existing debt, not granting new
# permission. Growth without them is an allowlist.
#
# Seeded statically — every module whose resolved test file never mentions it —
# because measuring all 539 candidates takes about two hours. An over-broad seed
# is inert while the module stays under the floor, and blocks the moment it
# clears it, which is the direction that costs nothing.
#
#   python scripts/pre_commit_coverage.py --adopt
#
# replaces the seed with the exact measured set.
