# Page sweep audit — 2026-07-26

Source: `frontend/scripts/page_sweep.mjs` run against production
(`https://hopefx.site`), 75 routes × 3 viewports. Raw data in
`frontend/report.json` on the VPS.

**Result: 73/75 pages clean.** Structurally the app is in far better shape than
the individual screenshots suggested. What remains is a small number of
*systemic* issues repeated across many pages, not 75 separate problems.

## Important caveat: this run was NOT authenticated

Every failing request is a `401`:

```
2×  401 POST /api/auth/refresh
1×  401 GET  /api/monetization/marketplace/strategies?sort_by=popular&limit=50
1×  401 GET  /api/monetization/marketplace/stats
1×  401 GET  /api/monetization/marketplace/subscriptions
1×  401 GET  /api/nocode/templates
```

So the sweep ran as an anonymous visitor. "73/75 clean" therefore covers the
public surface plus correctly-redirecting protected routes — it does **not**
audit the logged-in app. Trade, the AI pages, Auto-Heal and the dashboards were
never actually rendered, which is exactly where the known `NaN` / `No feed` /
frozen-price problems live.

**Re-run authenticated before trusting the pass rate:**

```bash
cd ~/HOPEFX-AI-TRADING/frontend
HOPEFX_URL=https://hopefx.site HOPEFX_USER=superadmin HOPEFX_PASS='...' \
  node scripts/page_sweep.mjs --save-auth --route=/dashboard
node scripts/page_sweep.mjs --out=report.json | tee sweep.log
```

One genuine finding even from the anonymous run: `POST /api/auth/refresh`
returning 401 twice suggests the SPA attempts a token refresh with no token
present. Harmless but noisy, and it means a real 401 on that endpoint is
indistinguishable from this one in the logs.

## 1. Tap targets below 24px — 12 pages desktop, 12 tablet, 10 mobile

The single most widespread issue. WCAG 2.2 sets 24px as the floor; Apple's HIG
recommends 44px. Nearly every offender is a footer or nav link sized by its text
with no padding:

| element | size | pages |
|---|---|---|
| `a "⌂"` | **7×11** | /pricing |
| `a "legal@hopefx.ai"` | 99×16 | /terms, /risk-disclosure |
| `a "Read the full FAQ on GitHub"` | 170×16 | /docs |
| `a "support@hopefx.io"` | 126×17 | /pricing |
| `input` | 165×18 | /upgrade, /transparency |
| `a "← Landing"` | 58×18 | /upgrade, /transparency |
| `a "Docs"` | 29×18 | several |
| `a "Status"` | 36×18 | several |
| `a "Back to home"` | 103×20 | /privacy |
| `button "Terms of Service"` | 103×20 | /terms |
| `a "Home"` | 34–37×20 | /docs, /pricing |

A 7×11px home icon is effectively untappable on a phone. Fix centrally: give
footer/nav links `min-height: 24px` (44px on touch) and vertical padding, rather
than patching each page.

## 2. Truncated sidebar labels — 6 pages desktop, 6 tablet

Always the same four, always clipped by their container:

```
span "AI Chart Bot" | span "AI Chart Dashboard" | span "Nuclear AI" | span "Copy Trading"
```

The sidebar nav is too narrow for its own longest labels, so they are cut off
mid-word. Notably this happens at **desktop 1440**, not just on mobile — so it
is a fixed-width sidebar problem, not a responsive one. Either widen the
sidebar, shorten the labels, or allow two lines.

## 3. Two `<h1>` elements — /pricing, /upgrade

Both pages render two `<h1>`s. Breaks document outline for screen readers and
splits SEO signal. One `h1` per page; demote the second to `h2`.

## 4. "main content region is empty" — /upgrade, /transparency, and mobile on several

Flagged where `main`/`[role=main]`/`#root > div` contains under 20 characters of
text. Two possibilities and they need separating before acting:

- genuinely empty — the page renders a shell with no content for an anonymous
  visitor (plausible for /upgrade, which needs a plan context)
- **a false positive in my own checker** — if the real content sits in a sibling
  of `#root > div`, the heuristic looks at the wrong node

Verify by eye at `https://hopefx.site/transparency` before changing code. If the
page looks fine, the checker needs fixing, not the page.

## 5. Three different email domains, none of which is the live one

```
support@hopefx.io     (/pricing)
privacy@hopefx.io     (/privacy)
legal@hopefx.ai       (/terms, /risk-disclosure)
```

The site runs on **hopefx.site**. So the contact addresses on your legal pages
point at two domains you may not own, inconsistently — `.io` on two pages and
`.ai` on two others. For Terms and Risk Disclosure specifically, an
undeliverable contact address is a compliance problem, not a typo.

Decide the canonical domain and make all three consistent.

## 6. Third-party font CDN on every page

```
third-party: fonts.googleapis.com, fonts.gstatic.com
```

Not a bug — informational. Worth knowing that every page load reaches Google,
which is a GDPR consideration for EU users (the VPS is in Paris) and a
render-blocking dependency. Self-hosting the two font families removes both.
