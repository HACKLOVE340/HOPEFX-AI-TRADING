# AI Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `executing-plans` (or
> subagent-driven development) to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the HOPEFX AI Core — a gateway, guardrails, tool bus, sandbox,
evals gate, cache and operator page — on top of the governance shell the v0
agent already wrote, after first making that shell's gates real.

**Architecture:** `v0/hopefx-remediation` contributed a fail-closed *governance
state machine*: lifecycle contracts, approval/checkpoint/validation ordering,
rate limits and an admin API. It has no engine — no model is ever called, and
its terminal verbs return simulations. This plan keeps the shell (it is good),
repairs five places where it reports success for work that did not happen, then
builds the engine underneath it in dependency order.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.x, pytest;
React 18 + TypeScript + Vite, TanStack Query.

**Spec:** `docs/audit/AI_CORE_SPEC.md` (§2 architecture spine, §3 the nine
concepts, §12 open items). Companion: `docs/audit/TODO.md` items 13–19.

**Source branches:** `claude/add-new-skills-lys862` (this branch, 158 commits of
audit fixes, PR #315) and `origin/v0/hopefx-remediation` (94 commits, branched
from `main@cc7203fe`).

## Global constraints

Every task inherits these. Not negotiable, not restated per task.

* Develop and push only on `claude/add-new-skills-lys862`.
* `ruff check .` clean; `pre-commit run --all-files` clean. Never `--no-verify`.
* Full gate before claiming done:
  `pytest tests/ -m "not slow and not e2e" --cov --cov-config=.coveragerc --cov-fail-under=70 --asyncio-mode=auto --timeout=120 -q`
* Never weaken a risk gate, kill switch, or staleness/drift check.
* Never commit secrets. `prop_firm_mode.json` and `.env.example` hold placeholders only.
* New code goes in `backtesting/`, `strategies/`, `data_layer/` — never the legacy shims.
* Never recreate a top-level `websocket/` package.
* **Every fix ships with a test that fails on the pre-fix tree.** Run it against
  the old code and watch it fail. A test that has never failed proves nothing.
* Compliance-critical paths stay hard-coded (spec §3 concept 9): drawdown limits
  and prop-firm rules are never delegated to a model.

# Part 1 — What the v0 agent actually built

94 commits, 72 files, ~3,200 lines of code (plus a 10,402-line `uv.lock`).
Branched off `main@cc7203fe` (today 13:34), so it is current with main.

## 1.1 What is genuinely good

**`core/ai_contracts.py` (206 lines).** Frozen dataclasses with validation in
`__post_init__` and canonical SHA-256 hashing over sorted JSON. A
`StrategyLifecycle` StrEnum with an explicit `_ALLOWED_TRANSITIONS` table:
research → validated → paper_pending → paper_active → live_pending_approval →
live_approved, with `RETIRED` reachable from every state and terminal. Illegal
transitions raise. `HumanApproval` refuses a live scope without a reason.
`DecisionEvidence` refuses to exist without model version, checksum, feature
schema hash and snapshot time. This is the right shape for an audit trail.

**Gate ordering in `api/safe_agent_platform.py`.** `execute_proposal` requires,
in order: status is `approved_pending_execution` → approval window not expired →
exact confirmation string → a checkpoint exists → a *passed validation in the
selected environment*. Repairs and upgrades require two approvals. That
sequencing is better than most production change-management code.

**Honest self-description in most terminal verbs.** `execute_supervisor_task`
returns `status: "completed_dry_run"` with every tool call marked
`simulated_no_side_effect`; `model_health` returns `"provider_call":
"not_performed"`. Where nothing happens, most of the code says so.

**Secret hygiene.** `_save_state` strips `secret`, `token_value`,
`access_token`, `refresh_token` before persisting integrations. `GET
/integrations` returns `"secret_values": "never_returned"` and means it.

**42 new tests, all passing** — verified in a merged worktree, not asserted.

## 1.2 Five defects, each proven by execution

Not code-reading opinions. Each was reproduced by running the code.

### D1 · The strategy execution gate is disabled by its own default argument · HIGH

`StrategyExecutionBoundary.evaluate` short-circuits `ExecutionScope.RESEARCH`
to `allowed=True` before any check. Both new call sites default to that scope:

```
dynamic_registry.activate_strategy(self, version_id, scope=ExecutionScope.RESEARCH, approval=None)
strategy_orchestra.activate_ai_strategy(self, strategy_id, scope=ExecutionScope.RESEARCH, approval=None)
```

Every production caller omits the argument:

```
api/dynamic_strategies.py:160   await registry.activate_strategy(request.version_id)
api/dynamic_strategies.py:232   await registry.activate_strategy(latest.version_id)
api/dynamic_strategies.py:242   await registry.activate_strategy(latest.version_id)
api/nocode.py:170               await registry.activate_strategy(version_id)
api/brain.py:301                await registry.activate_strategy(version_id)
```

Measured, with the weakest possible candidate (no validation, no evidence, no
approval):

```
scope=research  allowed=True   code=RESEARCH_ALLOWED
scope=paper     allowed=False  code=VALIDATION_REQUIRED
scope=live      allowed=False  code=VALIDATION_REQUIRED
```

The gate denies paper and live correctly — and nothing ever asks it for paper or
live. Past the boundary, `activate_strategy` sets `version.state =
StrategyState.ACTIVE` and registers it in `self._active`: a real activation, not
a research-scoped one. So the scope argument describes what the caller claims,
not what happens. **This is the audit's signature defect in a new costume: not
"never invoked" but "invoked with a default that makes it a no-op."**

### D2 · The research-evidence gate checks that a string is non-empty · HIGH

`StrategyExecutionBoundary` blocks paper and live unless
`candidate.research_validation_hash.strip()` is truthy, with the reason
"replay, walk-forward, leakage, slippage, and model-quality evidence is
required". `ResearchCandidate.transition()` enforces the same.

But `research_validation_hash` is a plain `str = ""` field that any constructor
may set to anything, and nothing binds it to real evidence. Every occurrence in
the repository:

```
core/ai_contracts.py:142                       research_validation_hash: str = ""      # declaration
core/ai_contracts.py:156                       ... not self.research_validation_hash.strip()
strategies/strategy_execution_boundary.py:44   ... not candidate.research_validation_hash.strip()
tests/unit/test_ai_contracts.py:24             research_validation_hash="research-evidence-sha"
tests/unit/test_strategy_execution_boundary.py:17  research_validation_hash="research-evidence-sha"
```

**Zero production assignments.** The gate is satisfied by the literal string
`"x"`, and the reason code then claims five validations occurred.

Meanwhile the module that computes that evidence —
`ml/research_validation_gate.evaluate_research_validation`, which checks replay,
walk-forward, leakage, slippage costs and model quality — has **no production
importer**. Neither does `ml/model_quality_gate.ModelQualityGate`. Both are
imported only by their own tests. `docs/ai_change_ledger.md` says of the quality
gate: *"Rollback: remove only new gate call sites"* — there are none.

### D3 · `validate_proposal` returns "passed" without validating · HIGH

The status is assigned by an expression over the environment *name*:

```python
"status": "passed" if request.environment in {"sandbox", "paper"} else "blocked_until_paper_passes",
"checks": {"secrets_redacted": True, "live_trading_disabled": True,
           "rollback_checkpoint_planned": True,
           "checkpoint_present": bool(proposal.get("checkpoints")),
           "human_approval_present": proposal["status"] == "approved_pending_execution"},
```

Three of the five "checks" are literals. Nothing is inspected. Measured against
a proposal with `changes={"delete": "everything"}`, no checkpoint and no
approval:

```
validate_proposal(env=sandbox) -> status=passed  checks={... checkpoint_present: False, human_approval_present: False}
validate_proposal(env=paper  ) -> status=passed  checks={... checkpoint_present: False, human_approval_present: False}
```

The two checks that *are* real report `False` and are ignored by the status.
And `execute_proposal` requires "a passed validation in the selected
environment" — which this endpoint always supplies. **This is item 12's defect
(F104, a gate that cannot fail) reproduced inside the AI Core.**

### D4 · `run_diagnostics` claims durable evidence and stores none · MEDIUM

The endpoint builds an `evidence` dict, calls `_save_state(user.sub)` — which
persists only `_PROPOSALS`, `_APPROVALS`, `_INTEGRATIONS`, `_TASKS`, `_ROUTES` —
and returns `"evidence_retention": "persisted_in_audit_store"`. `evidence` is a
dead local. Measured:

```
run_diagnostics returned run_id  : diag-9a04a24cfbde
  claims evidence_retention      : persisted_in_audit_store
  run_id findable in config_store: False
```

The `run_id` handed to the operator refers to nothing retrievable. Separately,
the two "findings" it returns are hardcoded literals, not observations.

### D5 · The approval ledger reports success on a failed write · MEDIUM

`config_store.set` returns `bool` — "True if at least the DB write succeeded" —
and logs `ConfigStore.set: DB write failed` otherwise. `_save_state` calls it
five times and **ignores every return value**. When the DB write fails, state
survives only in module-level Python lists and the endpoint still returns
success to the operator. This fires today: the proof run above emitted
`DB write failed` for all five keys while every endpoint returned 200.

Compounding it: `_PROPOSALS`, `_APPROVALS`, `_TASKS`, `_ROUTES` are module-level
lists mutated in place, loaded once by `_load_state()` **at import time**. Under
more than one uvicorn worker each worker holds a private copy and persists it
wholesale — last writer wins, and approvals recorded in one worker are invisible
to the next. (Same shape as F139: state frozen at import.)

### D6 · Frontend: a scan that fabricates a result, and jams · MEDIUM

`VisionScanner.scan()` in `VisualIntelligenceWorkspaces.tsx`:

```tsx
const scan = async () => {
  setStatus('processing');
  await new Promise((resolve) => window.setTimeout(resolve, 650));
  if (status !== 'processing') return;
  setResult('Visual interpretation is ready for review. Provenance: camera frame, ...');
  setStatus('captured');
};
```

Two bugs in five lines. The result string is fabricated — it sleeps 650 ms and
declares an interpretation ready, having analysed nothing. And it never runs:
`status` is captured by the closure at render time, so after `setStatus('processing')`
the awaited check still reads the old value `'captured'`, `'captured' !== 'processing'`
is true, and the function returns early. The panel jams on "Processing" with a
disabled button, permanently.

Also decorative: the `HologramPanel` "Analyze state" and "Explain decision"
buttons only call local `setState` — no request is made.

## Phase 2 — The engine (items 13, 17, 14, 19, 16, 15, 18)

Order is dependency-driven: gateway first because everything routes through it;
guardrails before the tool bus so the bus is never briefly unguarded.

Each of these is a subsystem, and per the `writing-plans` scope rule each gets
its own plan document with full step-level detail, written immediately before it
is executed. Defined here: the deliverable, its interface, and its done
condition — so the sequencing and the contracts between them are fixed now.

### Task 7 — AI Gateway (item 13)
**Deliverable:** `ai/gateway/` — the single entry point for every model call.
**Interface:** `async def call(request: ModelRequest, *, operator: str) -> ModelResponse`,
raising `BudgetExceeded`, `ProviderTimeout`, `ProviderUnavailable`.
Emits exactly one `ModelCallAudit` record per call (prompt hash, model, latency,
tokens, cost, outcome) — never the prompt itself.
**Absorbs:** v0's `_MODELS`, `POST /models/route`, `_consume_research_budget`.
**Done when:** `api/brain.py` no longer calls ollama directly; a test asserts no
module outside `ai/gateway/` imports a provider SDK; `GET /models/health`
performs a real probe instead of returning `provider_call: not_performed`.

### Task 8 — Guardrails (item 17)
**Deliverable:** `ai/guardrails/` — input fencing and output validation.
**Interface:** `screen_input(text) -> ScreenedInput` (promotes
`_reject_untrusted_instructions`), `validate_output(raw, schema) -> ParsedOutput`,
raising `GuardrailViolation`.
**Pattern to follow:** `news/geopolitical_llm.py` (F261) — fenced untrusted
input, strict parsing, severity ceiling for uncorroborated claims.
**Done when:** every `ai/gateway` response passes `validate_output` before any
caller sees it, asserted by a test that bypassing it fails.

### Task 9 — MCP tool bus (item 14)
**Deliverable:** `ai/tools/` — typed tool dispatch.
**Interface:** `async def invoke(tool: str, args: BaseModel, *, operator: str, approval: HumanApproval | None) -> ToolResult`.
**Must:** route every call through `enforce_agent_action` (F260, already wired to
seven predicates) **and** `ToolPermissionRegistry.review` (v0's, currently with
one importer). This is the task that gives both something to gate.
**Done when:** a test asserts no tool executes without passing both, and
`execute_supervisor_task` dispatches real tools instead of returning
`simulated_no_side_effect`.

### Task 10 — Sandbox (item 19)
**Deliverable:** `ai/sandbox/` — real isolated execution.
**Interface:** `async def run(code: str, *, timeout_s: float, net: bool = False) -> SandboxResult`.
**Note:** v0's `security/ai_repair_sandbox.py` is a static screen + `py_compile`,
not a sandbox. Keep it as a pre-filter; it is not the containment boundary.
**Done when:** an agent-authored strategy runs end-to-end against paper data
with no route to a real venue, proven by a test that a live-broker call from
inside the sandbox raises.

### Task 11 — Evals gate (item 16)
**Deliverable:** `ai/evals/` — scored suite plus promotion gate.
**Done when:** sandbox → live promotion is refused on a failing score, and
`validate_proposal` (Task 3) delegates to this rather than to its own checks.
Depends on Task 10.

### Task 12 — Response cache (item 15)
**Deliverable:** `ai/cache/` — keyed on prompt + model + tool state, explicit
invalidation. Sits in front of the gateway (spec §3 concept 5).
**Done when:** a repeated identical query does not reach the paid tier, and a
tool-state change invalidates the entry, both asserted.

### Task 13 — AI Core page (item 18)
**Deliverable:** `frontend/src/pages/AICore.tsx` — what the agent did, proposed,
what was refused and why.
**Read first:** `.claude/skills/ui-ux-pro-max/SKILL.md`; the other 71 pages
follow it. Absorbs v0's `ProfessionalControlPlane.tsx` and
`VisualIntelligenceWorkspaces.tsx`.
**Done when:** every panel reads a real endpoint, and no control is decorative —
the D6 rule, applied page-wide.
