# Chart data path — 2026-07-27

Follow-up to `AUDIT_2026-07-26.md`, which queued three questions about the AI
pages. Two are answered here from the source; the third still needs the
authenticated production sweep.

This session was static analysis only. There is no network path from this

so nothing below was measured against the live site — but the two defects are
provable from the code and are covered by tests that fail without the fix.

## Correction: the OHLCV endpoint exists

The previous session concluded "no OHLCV/candles endpoint found anywhere" and
flagged it as the leading hypothesis for empty charts. That was wrong.

`api/trading.py` serves `/api/trading/ohlcv/{symbol}` — the exact path
`features/chart-bot/services/chart-api.ts:fetchOHLCV` requests. The earlier grep
missed it because the decorator spans two lines and uses a `{symbol:path}`
converter, so a search for `@router.get("/ohlcv"` matched nothing.

Charts were empty for two unrelated defects in that endpoint's fallback chain.

---

## Bug 1 — the yfinance fallback never ran, for any symbol

`api/trading.py` called:

```python
df = t.history(period=period, interval=interval, auto_adjust=True, progress=False)
```

`progress` is a **`yf.download()`** parameter. `Ticker.history()` does not accept
it. `Ticker.history(*args, **kwargs)` forwards straight into
`PriceHistory.history`, whose signature is `(period, interval, start, end,
prepost, actions, auto_adjust, back_adjust, repair, keepna, rounding, timeout,
raise_errors)` — no `progress`, no `**kwargs`. Binding the call as written:

```
TypeError: got an unexpected keyword argument 'progress'
```

raised **before any network I/O**, on every request, for every symbol. It was
then swallowed by the surrounding `except Exception` and logged as

```
OHLCV yfinance direct fallback failed for %s: %s
```

which reads like an upstream data outage rather than a call-signature error.
That is why it survived: the log line blamed Yahoo.

This is the only one of nine `Ticker.history()` call sites in the repo that
passed `progress`. The sibling call at the same file's `/ai-analysis` endpoint
does not, and the price fallback in `get_prices` passes `progress=False` to
`yf.download`, where it is correct.

**Effect:** the middle tier of a three-tier fallback (price engine → yfinance →
bundled CSV) was dead. Any symbol whose price engine had no data fell straight
past yfinance to the CSV, which only covers XAUUSD daily/weekly — everything
else got a 503.

## Bug 2 — the chart's ticker map still pointed at delisted contracts

`b439bef` corrected `config/multi_source_feed.yaml` after verifying against
production that Yahoo no longer serves `GC=F SI=F PL=F CL=F BZ=F NQ=F YM=F`
(rows=0, "possibly delisted"). It did not touch the two hand-maintained copies
of the same mapping inside `api/trading.py`, which still resolved:

```
XAUUSD -> GC=F      XAGUSD -> SI=F      XPTUSD -> PL=F
US30   -> YM=F      NAS100 -> NQ=F      USOIL  -> CL=F      UKOIL -> BZ=F
```

Against the default `ALLOWED_SYMBOLS`
(`XAUUSD,EURUSD,GBPUSD,USDJPY,BTCUSD,ETHUSD,AUDUSD,USDCHF`) only one of those is
reachable — but it is **XAUUSD**, the instrument this platform exists to trade.
The other seven allowed symbols were already correct, which is why gold looked
uniquely broken.

The second copy sits in `get_prices` "Path 3", the yfinance price fallback used
in API-only mode. Same dead tickers for gold and silver — a plausible
contributor to the frozen-price symptom in the previous audit.

### Fix

Both maps now resolve through `_yf_ticker_map()`, which reads
`yfinance_ticker` from `config/multi_source_feed.yaml`. That file is the one
place a ticker can now be wrong, and it is the copy that gets verified against
production.

An empty ticker is meaningful and is preserved as "Yahoo does not serve this
instrument — skip the source", matching `data_feed/sources/yfinance_source.py`.
For metals the endpoint now skips yfinance immediately instead of spending a
20-second timeout on a dead contract.

**No ETF substitution**, per the reasoning in `b439bef`: GLD trades near $390
against spot gold near $4,070. A plausible wrong price on XAUUSD is far more
dangerous than a visibly absent one.

## What this does and does not fix

With both fixes, tier 2 works again for the seven non-gold allowed symbols:
EURUSD, GBPUSD, USDJPY, AUDUSD, USDCHF, BTCUSD, ETHUSD should serve bars at
every timeframe from yfinance whenever the price engine has nothing.

**Gold is not fixed by this change, and cannot be fixed in code.** XAUUSD now
correctly resolves to "no yfinance ticker", so its chart still depends on:

| timeframe | source | status |
|---|---|---|
| 1d / 1w | bundled `data/XAUUSD_40Y.csv` | works, back to ~2000 |
| 1m–4h | price engine only | **still empty without an API key** |

Gold intraday has no data source in the current configuration. That is a
provisioning gap, not a bug: it needs `TWELVE_API_KEY` (free tier covers
`XAU/USD`, already wired in `multi_source_feed.yaml`) or `ALPHA_VANTAGE_KEY`.
Until one is set, expect a 503 with `error: ohlcv_unavailable` on gold intraday
and the frontend's "data unavailable" state. **Setting that key is the single
highest-value next action for the chart pages.**

## Queued item 3, resolved: the real AI page components

The previous scan reported "0 calls" for six of seven pages because it guessed
the file paths. The routes in `src/App.tsx` map to:

| route | component file |
|---|---|
| `/ai-chart` (AI Chart Bot) | `src/features/chart-bot/components/ChartDashboard.tsx` |
| `/ai-chart-dashboard` | `src/pages/AIChartDashboard.tsx` |
| `/terminal` | `src/pages/Trading.tsx` |
| `/nuclear` | `src/pages/NuclearDashboardPage.tsx` |
| `/intelligence` | `src/pages/AIIntelligence.tsx` |
| `/ai-strategy` | `src/pages/AIStrategyGenerator.tsx` |
| `/ai-assistant` | `src/pages/AIAssistant.tsx` |

Two guesses were wrong in a way that explains the empty scan: `/terminal`
renders `pages/Trading.tsx` (not a `Terminal.tsx`), and `/ai-chart` renders from
`features/chart-bot/`, not `pages/`.

Only `/ai-chart` consumes OHLCV directly (`useOHLCV` in `ChartDashboard.tsx` and
`CoreChart.tsx`); `/nuclear` has one chart import. **The other five pages do not
use bars at all**, so their failure modes are unrelated to everything above and
are still unmeasured. Their documented endpoints:

- `/intelligence` → `/api/ml/health`, `/api/signals/active`, `/api/signals/analytics`
- `/ai-strategy` → `/api/brain/generate-strategy`, `/api/brain/deploy-strategy`
- `/ai-assistant` → `/api/chat`
