Security & Privacy

HOPEFX is built with security-first principles. Every layer of the platform — from authentication to data storage — is designed to protect your account and trading data.

Certifications & Standards

AES-256 Encryption JWT + Refresh Tokens TOTP 2FA Rate Limiting HTTPS / TLS 1.3 CORS Policy SQL Injection Prevention OWASP Top 10 Mitigations

Authentication

JWT Access & Refresh Tokens

Short-lived access tokens (15 min) paired with rotating refresh tokens. All tokens are signed with HS256 and validated on every request.

Two-Factor Authentication (2FA)

TOTP-based 2FA via any authenticator app (Google Authenticator, Authy, etc.). Enabled per-user from account settings. Backup codes are provided at setup.

Rate Limiting

Authentication endpoints are limited to 10 requests per 60 seconds per IP. Trading endpoints are limited to 60 requests per minute per user. Violations return HTTP 429.

Data Protection

  • All passwords are hashed with bcrypt (cost factor 12) — plaintext passwords are never stored.
  • Database connections use TLS. Sensitive fields are encrypted at rest with AES-256.
  • API keys and broker credentials are stored in environment variables or a secrets manager — never in source code or the database.
  • Audit logs record every privileged action with timestamp, user ID, and IP address.
  • Session tokens are invalidated on logout and password change.

Infrastructure

  • All traffic is served over HTTPS with TLS 1.2+ enforced. HTTP is redirected to HTTPS.
  • Security headers: Strict-Transport-Security, X-Content-Type-Options, X-Frame-Options, Content-Security-Policy.
  • Redis connections support TLS and password authentication.
  • Docker images are scanned for vulnerabilities via Snyk and CodeQL on every push.
  • Dependency updates are automated via Dependabot with weekly security patches.

Kill Switch & Risk Controls

The platform includes a hardware-level kill switch that immediately halts all trading activity and closes open positions when triggered. It propagates across all pods via Redis pub/sub, ensuring no orders are placed during a security incident or system anomaly.
